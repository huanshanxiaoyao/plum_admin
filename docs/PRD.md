# Plum 管理后台产品需求文档

- 文档版本：v0.4
- 文档状态：Ready for Development
- 更新时间：2026-08-30
- 产品范围：Plum 内部管理后台长期蓝图；本文明确标注一期交付边界

## 1. 背景

Plum 已具备面向普通用户的角色浏览、对话、角色创建、媒体上传、内容审核、发布、订阅基础记录和钱包能力，但产品、运营、审核人员目前缺少统一、低门槛的内部管理入口。

现有管理能力主要分散在后端静态页面和若干 Admin API 中，覆盖内容审核、模型配置、评测和调试等专业场景，不适合日常角色管理、创作者管理、用户和订阅查询，也不具备完整的员工身份、细粒度权限和一致的操作审计体验。

本项目将在独立仓库 `plum_admin` 中建设 Plum 管理后台，并尽量复用现有后端领域能力。后台不是新的业务事实源，不直接访问数据库，不复制角色发布、审核、订阅或钱包逻辑。

## 2. 产品目标

### 2.1 核心目标

1. 为产品、运营、审核和管理员提供统一的 Plum 内部工作台。
2. 支持查看、搜索和管理官方角色与用户创作角色。
3. 支持创建和上传官方角色，并复用现有审核和发布流程。
4. 支持查看创作者资料、作品和表现，并管理创作资格。
5. 支持查看用户的 Plum 资格、订阅基础状态、钱包余额和消费摘要。
6. 建立员工级身份、权限控制和可追溯的操作审计。
7. 在不破坏账号隔离、内容版本和审核不变量的前提下，控制后端改造范围。

### 2.2 成功标准

- 产品或运营人员不需要登录生产机器、执行 SQL 或使用共享 Admin Token，即可完成日常查询和授权范围内的管理操作。
- 所有高风险写操作都可追溯到具体员工，并记录原因、对象和结果。
- 官方角色与 UGC 角色继续使用统一的 Work、Version、Character 和 Moderation 业务链路。
- 所有后台角色默认都看不到完整手机号、邮箱、对话正文、Prompt 等敏感信息。
- 后台故障不影响 `plum.top` 用户侧主站和聊天服务。

## 3. 一期范围

本文保留 Plum 管理后台的长期产品蓝图，不因一期暂缓而删除未来功能。功能标题下使用以下状态：

- **一期**：本轮开发、联调和验收必须交付。
- **后续**：保留需求方向，但不进入本轮开发、API 承诺和验收。

一期包含：

- 员工飞书登录自注册、按 `open_id` 禁用、Admin/Operator 两角色 RBAC。
- 工作台中可由一期数据稳定计算的基础指标和最近操作。
- Character、Work/草稿的列表、详情和版本摘要。
- 官方角色表单创建、媒体上传、草稿保存、提交现有审核链路和发布。
- 角色下架与恢复。
- 创作者列表、详情、创作资格限制/恢复和内部备注。
- Plum 用户列表、详情和 Membership 管理。
- Subscription 基础记录只读查询；不把方案记录描述为支付成功。
- 一期写操作审计和后台成员管理。

以下内容明确不属于一期，但相关产品需求保留在本文供后续规划：

- 运营活动、活动编排、专题页和投放计划。
- 优惠券、邀请码营销、拉新归因和渠道漏斗。
- 支付渠道接入、自动续费、退款、发票和对账。
- 钱包余额、Ledger 和人工余额操作。
- 创作者分成、提现和财务结算。
- 独立内容审核工作台、人工领取任务和审核决策页面；官方角色仍复用后端已有审核链路。
- 标签、Badge 和 Feed 排序的管理能力。
- CSV、JSON、Excel、TXT、ZIP 等导入导出。
- 大规模内容推荐算法配置。
- 直接编辑用户对话、Persona、记忆或 Prompt 正文。
- 取代现有评测控制台、模型调试控制台和系统运维工具。
- 面向创作者或普通用户开放的自助门户。

如果后续业务明确需要运营活动，应单独立项，不在角色排序或 Badge 中隐式扩展活动语义。一期不为上述后续能力预建空表、空接口或不可验证的 UI 入口。

## 4. 用户角色

### 4.1 Operator

适用于产品、运营和审核等日常后台使用人员。

- 一期查看工作台、角色、创作者、用户、订阅和脱敏审计数据。
- 创建、编辑、提交审核和发布已审核通过的官方角色。
- 执行角色下架，但必须填写原因；角色恢复仅允许 Admin 执行。
- 查看创作者表现，暂停或恢复创作资格并维护内部备注。
- 不允许恢复已下架角色、管理 Plum Membership、管理后台成员或查看敏感正文。

### 4.2 Admin

适用于少量系统负责人。

- 包含 Operator 的全部权限。
- 恢复已下架角色。
- 执行 Plum Membership 禁用或恢复等高风险操作。
- 管理后台成员、角色和状态。
- Admin 也不拥有普通明文访问权限；特定敏感信息仍需沿用独立临时审批机制。

### 4.3 RBAC 权限矩阵

后端角色与 Capability 是唯一授权事实，前端只根据 Plum 专属 `/admin/plum/me` 返回的角色和 Capability 裁剪导航与操作入口。Operator 承担绝大多数日常工作；只有恢复已下架角色、管理 Plum Membership 和管理后台成员需要 Admin。其他两个业务的后台身份与权限不属于本项目，也不能通过本后台访问。

| 业务能力 | 交付阶段 | Operator | Admin |
| --- | --- | --- | --- |
| 查看工作台、角色、创作者、用户、订阅和审计摘要 | 一期 | ✓ | ✓ |
| 创建、编辑、提交审核和发布官方角色 | 一期 | ✓ | ✓ |
| 下架 Character | 一期 | ✓ | ✓ |
| 暂停或恢复创作者资格、维护内部备注 | 一期 | ✓ | ✓ |
| 恢复已下架 Character | 一期 |  | ✓ |
| 禁用或恢复 Plum Membership | 一期 |  | ✓ |
| 添加、改角色或禁用后台成员 | 一期 |  | ✓ |
| 管理标签、Badge 和 Feed 基础排序 | 后续 | 待定 | 待定 |
| 领取和处理审核任务 | 后续 | 待定 | 待定 |
| 钱包和 Ledger 查询 | 后续 | 待定 | 待定 |
| 普通明文访问 | 不规划普通入口 |  |  |

补充规则：

- 一期不授予任何角色普通明文读取权限，包括 Admin。敏感正文仍必须走既有临时审批机制，且不在本后台提供普通入口。
- 日常运营接口返回脱敏登录标识，不包含完整手机号或邮箱。
- Operator 的官方角色提交仍受现有审核状态机约束，不能绕过自动审核或静默覆盖历史结论；独立审核工作台不在一期。
- 一期不建设通用审批流。Operator 需要三类高级操作时线下联系 Admin；Admin 独立检查对象、填写原因并执行，审计记录真实 Admin，不允许代操作或临时提升 Operator 权限。
- Admin 不能删除系统中最后一个 Active Admin。

## 5. 信息架构

后台信息架构如下；后续页面一期不显示入口：

| 一级模块 | 交付阶段 |
| --- | --- |
| 工作台 | 一期 |
| 角色管理 | 一期 |
| 创作者管理 | 一期 |
| 用户管理 | 一期 |
| 订阅 | 一期，只读 |
| 操作审计 | 一期，仅覆盖一期动作和非敏感元数据 |
| 后台成员 | 一期，仅 Admin 可见 |
| 钱包与 Ledger | 后续 |
| 内容审核工作台 | 后续 |
| 标签与 Badge | 后续 |

页面以信息密度、可扫描性和重复操作效率为优先，不采用面向消费者的营销式页面结构。

## 6. 功能需求

### 6.1 登录与账号

**交付阶段：一期。**

#### FR-AUTH-01 员工登录

- 一期使用飞书 OAuth 授权码流程登录，认证实现保持 Provider 可替换。
- 使用同一飞书应用返回的 `open_id` 作为稳定员工身份；企业邮箱允许为空，不按邮箱域自动授权。
- 登录流程不申请离线授权，不保存飞书 access/refresh token，也不要求 `auth:user_access_token:read`。
- 飞书应用“可用范围”仅包含产品、运营和管理人员；只有范围内成员可以完成 OAuth。
- 范围内成员首次登录时自动建立 Plum 后台员工记录，默认角色为 Operator、状态为 Active；不得因首次登录自动获得 Admin。
- 保存飞书回调返回的 `open_id`、`union_id`、`tenant_key`、姓名和可选头像；邮箱只在无需额外敏感权限即可获得时保存，不作为授权依据。
- 首个 Admin 通过受控的一次性 Bootstrap 建立；后续 Admin 只能由已有 Admin 授予。

#### FR-AUTH-02 会话

- 登录态使用 Secure、HttpOnly、SameSite Cookie。
- 会话过期后跳转登录页，不保留敏感页面内容。
- 支持主动退出，并立即失效当前后台会话。

#### FR-AUTH-03 权限反馈

- 页面和操作入口根据权限显示。
- 后端仍必须独立校验权限。
- 无权限访问返回统一的 403 页面，不将 403 伪装成系统错误。

### 6.2 工作台

**交付阶段：一期，但只展示一期数据能够稳定计算的指标和事项。**

#### FR-DASH-01 核心指标

默认展示：

- Plum 有效用户总数和近 7 日新增。
- 近 7 日活跃用户数。
- Active、Draft、Archived 角色数量。
- 官方角色与 UGC 角色数量。
- 创作者总数和近 7 日新增创作者数。
- 当前订阅方案分布。

指标必须标注统计口径和时间范围。无法获得的数据展示为空态，不使用模拟数字。

#### FR-DASH-02 待处理事项

- 发布失败或审核服务异常的官方角色草稿。
- 最近被下架的角色。
- 最近受到创作限制的创作者。

#### FR-DASH-03 最近操作

- 展示最近后台写操作的操作者、动作、对象、结果和时间。
- Operator 只能看到不含敏感前后值的摘要。

### 6.3 角色管理

**交付阶段：FR-CHAR-01 至 FR-CHAR-06 为一期；FR-CHAR-07 为后续。**

#### FR-CHAR-01 角色列表

角色管理分为“已生成 Character”和“Work/草稿”两个视图，避免将尚未发布的 Creation Draft 伪装成 Character。Character 视图支持以下查询和筛选：

- 角色 ID、名称和创作者名称搜索。
- 官方角色或 UGC 角色。
- Active、Archived、Takedown 等 Character 状态。
- General 或 Mature 内容评级。
- 标签、Badge、性别和发布时间。
- 按发布时间、更新时间、互动量和 Feed 顺序排序。

列表至少展示封面、名称、来源、创作者、状态、评级、当前版本、发布时间和关键互动数据。

Work/草稿视图展示 Draft、Pending Review、Rejected、Published、Archived 状态，并关联已发布的 Character ID；两类列表均使用服务端筛选和游标分页。

#### FR-CHAR-02 角色详情

角色详情包括：

- 当前公开字段和媒体预览。
- 所属 Work、当前 Character Version 和历史版本。
- 创作者信息和所有权类型。
- 标签、Badge、基础排序和统计。
- 审核状态、审核类别和审核引用。
- 最近管理操作记录。

私有 Prompt 和审核供应商原文默认不展示；如后续开放，必须沿用既有明文访问审批机制。

#### FR-CHAR-03 创建官方角色

- Operator 和 Admin 可以创建官方角色草稿。
- 第一版支持后台表单录入；JSON 批量导入为后续增强项。
- 字段与用户侧 Create 能力保持一致，包括名称、性别、立绘、简介、开场场景、角色设定、示例对话、回复规则、标签、内容评级和可见性。
- 保存草稿不触发审核。
- 提交发布前必须展示完整预览和必填项校验。

#### FR-CHAR-04 官方角色媒体上传

- 支持上传角色立绘。
- 复用现有图片大小、格式、解码、裁切和审核规则。
- 上传中的媒体只对有权限的后台人员可见。
- 上传失败不得生成残留的可发布角色。

#### FR-CHAR-05 审核与发布

- 提交后使用现有自动审核流程。
- 审核通过后才允许发布。
- 审核拒绝时展示可公开的拒绝类别和修订入口。
- 发布请求必须防止重复提交，并针对版本冲突给出明确提示。

#### FR-CHAR-06 下架与恢复

- Operator 和 Admin 可以下架角色。
- 下架前必须展示影响范围并要求填写原因。
- 下架后角色不再进入公开 Feed，也不能新建会话。
- 恢复前重新校验 Work、版本、审核和媒体仍满足发布条件。
- 下架和恢复都必须进入审计日志。

#### FR-CHAR-07 标签、Badge 和排序

**交付阶段：后续。**

- Operator 和 Admin 可以分配或移除现有标签、Badge。
- 可以调整 Feed 基础排序。
- 每次修改显示保存结果，并记录修改前后值。
- 本功能不得承载尚未定义的运营活动语义。

### 6.4 创作者管理

**交付阶段：一期。**

#### FR-CREATOR-01 创作者列表

创作者定义为在 Plum 拥有创作 Work 或已发布 Character 的平台用户。

列表支持按用户 ID、公开名称、状态和创建时间筛选，并展示：

- 公开资料。
- 草稿、已发布、被拒绝和被下架作品数量。
- 角色累计互动、点赞和收藏摘要。
- 当前创作资格。
- 最近创作和发布时间。

#### FR-CREATOR-02 创作者详情

- 查看创作者公开资料和内部状态。
- 查看其全部 Work、角色、版本和审核结果。
- 查看与该创作者有关的后台操作记录。
- 不默认展示与创作管理无关的对话正文或敏感身份字段。

#### FR-CREATOR-03 创作资格管理

- Operator 和 Admin 可以暂停或恢复用户的角色创建和发布能力。
- 暂停创作不等同于禁用用户登录，也不自动下架既有角色。
- 操作必须填写原因。
- 恢复操作必须保留原暂停记录，不覆盖历史。
- 被暂停的创作者在用户侧保存或发布时收到明确、稳定的业务错误。

#### FR-CREATOR-04 内部备注

- Operator 和 Admin 可以维护创作者内部备注。
- 备注不向创作者或普通用户展示。
- 备注修改进入审计日志。

### 6.5 用户管理

**交付阶段：一期；钱包字段和钱包摘要不在一期响应中。**

#### FR-USER-01 用户列表

支持按平台用户 ID、显示名称、Plum Membership 状态、注册时间和最近活跃时间筛选。

列表展示：

- 平台用户 ID。
- 脱敏后的登录标识。
- Plum Membership 状态。
- 当前订阅方案。
- 角色数、会话数和最近活跃时间摘要。

#### FR-USER-02 用户详情

- 查看基本账号信息和 Plum Membership。
- 查看订阅基础记录。
- 查看角色、会话数量及最近活动摘要。
- 默认不展示聊天正文、Prompt、Persona 或记忆正文。
- 敏感身份字段按权限和审计要求脱敏。

#### FR-USER-03 Membership 管理

- 仅 Admin 可以禁用或恢复用户的 Plum Membership。
- 操作前展示对登录、聊天和创作能力的影响。
- 必须填写原因并二次确认。
- 该操作只影响 `app_id=plum`，不得影响用户在其他产品的资格。

### 6.6 订阅与钱包

**交付阶段：FR-SUB-01 为一期；FR-SUB-02 和 FR-SUB-03 为后续。**

#### FR-SUB-01 订阅查询

- 查看 Plum 用户的最新订阅方案、状态、创建和更新时间。
- 支持按方案和状态筛选。
- 明确区分 Product Membership 与 Subscription，不将两者混为同一状态。
- 当前没有真实支付链路时，页面必须明确标识“仅产品方案记录，不代表已付款”。

#### FR-SUB-02 钱包查询

**交付阶段：后续。**

- 查看当前金币余额。
- 查看按时间倒序排列的账本摘要。
- 展示流水类型、金额、余额、来源和时间。
- 默认不提供人工改余额入口。

#### FR-SUB-03 导出

**交付阶段：后续。**

- 一期不提供任何数据导出。
- 后续如增加导出，需要独立权限、审计和下载有效期。

### 6.7 内容审核

**交付阶段：后续。** 一期官方角色只调用现有审核链路，不建设审核队列、领取任务或人工决策页面。

#### FR-MOD-01 审核队列

- 复用现有 Moderation Admin 队列和状态机。
- Operator 和 Admin 可以查看审核队列、领取任务并提交审核结论。
- 审核任务必须使用现有领取与并发规则，避免两人同时覆盖结论。

#### FR-MOD-02 审核详情

- 展示审核所需内容、供应商结论和历史操作。
- 明文内容访问沿用现有审批与审计边界。
- 审核决策不可静默覆盖历史决策。

### 6.8 标签与 Badge

**交付阶段：后续。**

#### FR-TAG-01 标签管理

- 查看标签编码、展示名称、状态和排序。
- Operator 和 Admin 可以创建标签，修改展示名称、排序和启停状态。
- 停用标签不删除历史版本中的标签快照。

#### FR-BADGE-01 Badge 管理

- 查看 Badge 编码、名称、样式和状态。
- 分配和移除角色 Badge。
- 不允许用 Badge 代替未定义的运营活动系统。

### 6.9 操作审计

**交付阶段：一期，但仅覆盖一期接口产生的操作和非敏感审计元数据。**

#### FR-AUDIT-01 审计内容

所有后台写操作必须记录：

- 员工 ID、角色和显示名称。
- 动作、资源类型和资源 ID。
- 操作原因。
- 请求 ID、结果和时间。
- 允许记录时的修改前后值摘要。

禁止在审计元数据中记录会话 Cookie、Bearer Token、完整 Prompt、聊天正文或支付凭据。

#### FR-AUDIT-02 审计查询

- 支持按操作者、动作、资源、结果和时间范围筛选。
- Operator 和 Admin 可以查看受控的非敏感审计元数据；两者都不能看到敏感正文或凭据。
- 审计记录不得从后台删除或就地修改。

### 6.10 后台成员

**交付阶段：一期。**

#### FR-STAFF-01 成员列表

- Operator 和 Admin 查看后台成员、飞书 `open_id`、可选邮箱、角色、状态、首次登录和最近登录时间。
- 不显示任何服务端密钥或身份提供方 Token。

#### FR-STAFF-02 权限管理

- Admin 可以按指定飞书 `open_id` 修改角色、禁用或恢复成员；一期不提供手工预注册入口。
- 禁用后该成员的新登录和所有后续后台请求立即被拒绝；已有 Cookie 不构成继续访问的依据。
- 不能移除系统中最后一个 Active Admin。

## 7. 关键业务流程

### 7.1 官方角色创建与发布

1. Operator 创建官方角色草稿。
2. 上传并预览立绘。
3. 填写角色字段并保存草稿。
4. 系统执行字段完整性和版本校验。
5. Operator 提交审核。
6. 自动审核返回 Approved、Rejected 或 Pending Review。
7. Approved 后 Operator 确认发布。
8. 系统原子更新 Work、Version、Character、Tag 和媒体引用。
9. 后台展示发布结果并写入审计日志。

### 7.2 UGC 角色下架

1. Operator 从角色详情发起下架。
2. 后台展示角色、创作者、活跃状态和影响说明。
3. Operator 填写原因并确认。
4. 后端校验权限和当前状态，执行状态迁移。
5. 角色立即退出公开分发和新会话入口。
6. 系统记录操作者、原因和前后状态。

### 7.3 暂停创作者资格

1. Operator 在创作者详情选择暂停创作。
2. 填写原因并确认是否需要另行处理既有角色。
3. 后端只更新 Plum 创作资格，不禁用平台用户或其他产品 Membership。
4. 用户侧后续创建或发布请求被稳定拒绝。
5. 恢复资格时追加新审计事件，不覆盖原暂停记录。

## 8. 通用交互要求

- 列表必须使用服务端筛选、排序和游标分页。
- 筛选条件应体现在 URL 中，刷新和复制链接后可恢复。
- 表格列宽稳定；加载、空数据、无权限和请求失败状态彼此区分。
- 所有写操作提供成功或失败反馈，禁止静默失败。
- 下架、禁用 Membership、暂停创作者等高风险操作需要原因和确认。
- 重复点击不得造成重复发布、重复扣费或重复状态迁移。
- 时间默认显示为用户浏览器时区，并提供绝对时间；后端统一返回带时区的 ISO 8601。
- 桌面端优先，同时保证常用只读页面在窄屏可用；不要求移动端完成复杂批量管理。

## 9. 数据与隐私要求

- 后台只通过服务端 BFF 访问 FastAPI，不允许浏览器直连 PostgreSQL。
- 浏览器不得获得 `ADMIN_TOKEN`、`ADMIN_STAFF_TOKEN` 或后台服务凭据。
- 用户查询必须固定 `app_id=plum`，避免跨产品数据泄露。
- 手机号和邮箱默认脱敏；Operator 和 Admin 都不因角色管理需求获得完整身份数据。
- 对话、Prompt、Persona 和记忆正文不属于普通后台页面的数据源。
- 任何明文访问继续使用既有的申请、批准、过期和访问审计机制。

## 10. 验收标准

确定性验收数据、角色样例和跨权限场景见 [验收样例](./ACCEPTANCE_SAMPLES.md)。一期只执行其中与一期范围对应的样例；Wallet 和 Moderation 样例保留供后续使用，不构成一期退出条件。该文档是后端测试 Fixture、前端 Mock 和 UAT 数据准备的共同输入。

### 10.1 通用验收

- 未登录用户无法访问任意后台业务页面和 API。
- 飞书回调拒绝 state 不匹配、签名篡改、过期或缺少 PKCE verifier 的请求。
- 飞书应用可用范围内的新成员首次登录后自动创建为 Active Operator，重复登录不重复建记录并更新 `last_login_at`。
- 不在飞书应用可用范围内的成员由飞书拒绝授权，后台不得使用邮箱域或通讯录导出绕过该边界。
- 后台成员状态为 Disabled 时无法继续访问。
- 前端隐藏和后端拒绝两层权限行为一致。
- 所有一期后台写操作都能在审计页检索到。
- 后台不可用时 `plum.top` 用户侧服务不受影响。

### 10.2 角色验收

- 可以查询官方和 UGC 角色，并按状态和创作者筛选。
- 可以完成一条官方角色从草稿、上传媒体、审核到发布的完整流程。
- 重复发布同一幂等请求只产生一个发布结果。
- 下架角色不会出现在公开 Feed，且无法新建会话。
- 无权限用户调用角色写接口返回 403。

### 10.3 创作者验收

- 可以从创作者查看其作品和审核状态。
- 暂停创作者后，该用户无法新建或发布角色，但仍可使用其他非创作功能。
- 恢复后创作能力重新可用，历史暂停记录仍可查询。

### 10.4 用户与订阅验收

- 用户列表只返回 Plum 范围内的数据。
- 可以查看 Membership 和 Subscription，且两种状态清晰区分。
- Operator 和 Admin 看到的手机号和邮箱均已脱敏。
- 禁用 Plum Membership 不影响同一平台用户的其他产品资格。

## 11. 迭代计划

### 一期：核心管理闭环

- 仓库和工程基础、员工登录、成员名单和两角色 RBAC。
- 工作台一期指标。
- Character、Work/草稿、创作者、用户、Subscription 和审计只读能力。
- 官方角色草稿、媒体上传、提交现有审核链路和发布。

- 后台成员管理和一期写操作审计。

- 独立审核工作台。
- 标签、Badge 和 Feed 基础排序。

## 12. 一期决策记录

以下决策于 2026-08-28 确认并冻结：

1. 员工登录使用飞书 OAuth 2.0；实现保持 Provider 可替换。
2. 生产后台域名使用 `admin.plum.top`。
3. 官方角色由固定的 `Plum Official` 创作者账号承接媒体和 Work 所有权。
4. Operator 可以下架角色，但只有 Admin 可以恢复角色。
5. 一期官方角色只支持表单录入，不支持 JSON、Excel 或 ZIP 批量导入。
6. 创作者内部备注使用单一当前备注，历史修改由不可变审计事件保留。
7. 一期不包含运营活动。
8. 一期不包含钱包、Ledger、支付、退款、续费或人工余额操作。
9. 一期不包含独立内容审核工作台；官方角色继续复用现有审核链路。
10. 一期不包含标签、Badge 和 Feed 排序管理。
11. 一期不提供普通明文访问入口，现有临时审批机制也不自动授予任何后台角色。
12. 一期不提供 CSV 或其他格式的数据导出。
13. 一期后台 RBAC 仅包含 Operator 和 Admin；Operator 覆盖日常工作，Admin 只额外承担角色恢复、Membership 和后台成员管理。
