# Plum 角色导入打包规范

- 文档版本：v1.0
- 更新时间：2026-09-05
- 适用入口：`https://admin.plum.top/imports`
- 适用人员：Plum 运营、内容制作与审核协作人员
- 关联说明：[角色导入使用说明](./CHARACTER_IMPORT_USER_GUIDE.md)

## 1. 开始前

从管理后台“角色导入”右上角进入“打包规范”，下载最新 CSV 模板。模板包含全部字段和一行可通过格式校验的示例数据，请在模板上修改，不要自行拼列名。

CSV 没有注释语法。不要增加“字段说明”行，每一行都会被当成角色数据解析。

## 2. ZIP 目录结构

```text
plum_characters_20260905_v1.zip
|-- manifest.csv
`-- images/
    |-- 001_luna.png
    `-- 002_kai.jpg
```

要求：

- ZIP 顶层只放一个 manifest 和一个 `images/` 目录，不要再套一层同名文件夹。
- `manifest.csv` 与 `manifest.jsonl` 二选一。日常运营推荐 CSV。
- 不接受 `.xlsx` 或 `.xls`。编辑完成后另存为“CSV UTF-8（逗号分隔）”。
- 文件名建议只使用 ASCII 字母、数字、短横线和下划线，避免中文文件名跨平台乱码。
- 不接受加密 ZIP、符号链接、绝对路径或包含 `..` 的路径。
- macOS 自动生成的 `__MACOSX/`、`.DS_Store` 会显示提示，但不会阻塞导入。

## 3. CSV 编辑注意事项

- 第一行必须是列头，列顺序不限，拼写必须与模板一致。
- 不认识的列、审核字段、状态字段、统计字段会被拒绝，不会静默忽略。
- 长文本中的换行必须包含在双引号内；字段内的双引号写成两个双引号。
- Excel 容易把长 ID 转成科学计数法。编辑前把 `character_id` 和平台用户 ID 列设置成“文本”。
- `row_key` 在同一个包内必须唯一，建议使用编号加英文短名，例如 `001_luna`。
- 字符数只是第一道限制。最终是否超限，以管理后台服务端预检显示的容量条为准。

## 4. 字段说明

| 字段 | 要求 | 取值或上限 | 说明 |
| --- | --- | --- | --- |
| `row_key` | 每行必填 | 64 字符 | 包内唯一稳定行标识，用于错误定位和结果对齐 |
| `display_name` | 每行必填 | 50 字符 | 角色名称 |
| `gender` | 每行必填 | `male` / `female` / `non_binary` | 角色性别 |
| `intro` | 每行必填 | 10,000 字符 | 角色简介，中文实际容量以预检为准 |
| `opening_scene` | 每行必填 | 10,000 字符 | 开场场景，中文实际容量以预检为准 |
| `character_settings` | 每行必填 | 20,000 字符 | 角色设定，与回复规则共享容量预算 |
| `creator_declared_rating` | 每行必填 | `general` / `mature` | 内容评级声明，平台审核可以上调实际评级 |
| `portrait_file` | 列必需、条件必填 | 255 字符 | 新建必填；更新留空表示沿用现有立绘 |
| `owner_platform_user_id` | 可选 | 100 字符 | 行级归属账号；留空使用页面选择的批次默认账号 |
| `character_id` | 可选 | 100 字符 | 留空表示新建；填写已有 ID 表示更新 |
| `example_dialogues` | 可选 | 10,000 字符 | 示例对话；更新时留空会清空原值 |
| `response_rules` | 可选 | 6,000 字符 | 回复规则；更新时留空会清空原值 |
| `tag_ids` | 可选 | 最多 10 个 | 使用竖线分隔，例如 `tag_healing|tag_daily`，不可重复 |
| `visibility` | 可选 | `public` / `private` | 留空使用 `private` |
| `portrait_crop` | 可选 | `x,y,width,height` | 0-1 归一化坐标；留空时居中裁成 9:16 |
| `avatar_crop` | 可选 | `x,y,width,height` | 0-1 归一化坐标；留空时居中裁成 1:1 |
| `note` | 可选 | 500 字符 | 只保留在导入结果中，不写入角色数据 |

## 5. 新建与更新

- `character_id` 留空：新建角色。
- `character_id` 填写已有角色 ID：为该角色发布新版本。
- 更新时预检会回显目标角色当前名称，必须确认 ID 没有填错。
- 更新不能改变角色归属账号。
- 更新是全量覆盖，不是增量修改。除立绘和归属账号的特殊规则外，可选字段留空会清空原值，不是“保持不变”。
- 更新行不更换立绘时，可以把 `portrait_file` 留空；如果填写图片路径，则会替换立绘。

## 6. 图片要求

| 项目 | 要求 |
| --- | --- |
| 格式 | JPEG、PNG、WebP，扩展名必须与真实格式一致 |
| 单张大小 | 不超过 8 MiB |
| 总像素 | 不超过 6,000 万 |
| 推荐原图 | 1080 x 1920（9:16） |
| 裁剪后立绘 | 至少 360 x 640，比例 9:16 |
| 裁剪后头像 | 至少 192 x 192，比例 1:1 |

同一张原图会生成 9:16 立绘和 1:1 头像。非 9:16 原图默认居中裁剪，可能切掉人物头部。优先提供 9:16 原图，必要时填写 `portrait_crop` 和 `avatar_crop`。

预检表只为前 60 行生成立绘缩略图，第 61-100 行显示图片文件名。这不影响校验或导入，后半部分需要人工按文件名核对图片对应关系。

## 7. 批次限制

- 一个 ZIP 最多 100 个角色。
- 一个 ZIP 不超过 600 MB。
- 全后台同时只能执行一个导入批次。
- 如果接近 600 MB，优先压缩图片。1080 x 1920 的 JPEG 通常不需要达到 8 MiB。

## 8. 压缩前检查

1. CSV 已保存为 UTF-8，列名与模板完全一致。
2. 没有说明行、多余字段或空的角色行。
3. 每个 `row_key` 唯一，图片路径与 ZIP 内文件逐字一致。
4. 更新行的 `character_id` 完整，并以文本格式保存。
5. 内容评级、图片和文本授权来源已经确认。
6. 归属账号正确，更新角色没有尝试变更归属。
7. 直接压缩 manifest 与 images 目录，没有额外顶层文件夹。

打包完成后按照[角色导入使用说明](./CHARACTER_IMPORT_USER_GUIDE.md)进行上传、预检和结果处理。
