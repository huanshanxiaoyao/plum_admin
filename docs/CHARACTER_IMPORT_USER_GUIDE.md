# Plum 角色导入使用说明

- 文档版本：v1.0
- 更新时间：2026-09-05
- 适用入口：`https://admin.plum.top/imports`
- 适用人员：具有日常运营权限的 Plum Operator 与 Admin
- 关联规范：[角色导入打包规范](./CHARACTER_IMPORT_PACKAGE_GUIDE.md)

## 1. 重要原则

- 生产导入会真实创建或更新角色，不是演示操作。
- 导入没有批次回滚。一行成功后不会因为其他行失败而撤销。
- 更新是发布新版本，并且是全量覆盖。必须从保留的源包修改。
- 系统不导出角色正文。源 ZIP 是后续修订时唯一的正文副本，必须妥善保留。
- 导入不会绕过机器审核或人工复核。
- 所有导入操作都会记录操作人、时间、原因、批次 ID 和逐行结果。

## 2. 上传前准备

1. 按照[打包规范](./CHARACTER_IMPORT_PACKAGE_GUIDE.md)制作 ZIP，并先保留一份不可变的源包。
2. 确认本批默认归属账号。更新已有角色时不能改变原归属账号。
3. 确认文本和图片拥有可发布权利，并完成 `general` / `mature` 内容评级。
4. 与内容复核同事确认处理窗口。大量内容进入待复核后，公开时间取决于复核速度。
5. 确认没有其他人正在执行导入。全后台同一时间只允许一个运行中的批次。

## 3. 选择 ZIP

1. 登录 Plum 管理后台，进入“角色导入”。
2. 选择或拖入一个 `.zip` 文件。
3. 浏览器会在本地解包并读取 manifest；选择文件本身不会写入生产数据。
4. 图片不会先上传到后台服务器。只有正式提交时，图片才从浏览器直传对象存储。

如果页面立即提示结构、编码、列名、图片路径或文件大小错误，返回源文件修正后重新压缩上传。

## 4. 预检

预检分为本地校验和服务端预检，两者都不会创建、更新或发布角色，可以反复执行。

逐行检查：

- 角色名称与 `row_key` 是否正确。
- 页面判断的是“新建”还是“更新”。
- 更新行回显的目标角色当前名称是否正确。
- 立绘是否与这一行匹配。前 60 行显示缩略图，第 61-100 行只显示文件名。
- 各文本块容量是否在允许范围内。
- 标签、枚举、归属账号和裁剪参数是否有效。
- 页面列出的错误和提示是否已经处理。

只有预检通过的行才会参与提交。有问题的行不会被偷偷忽略，应当修正后重传。

预检通过只代表格式、容量和目标关系正确，不代表内容一定通过机器审核或人工复核。

## 5. 确认与提交

1. 选择“批次默认归属账号”，核对公开名称和平台用户 ID。
2. 填写可追溯的导入原因，例如日期、内容项目和批次编号。
3. 勾选内容权利和分级声明。
4. 再次确认本批通过行数、新建/更新判断和立绘。
5. 点击提交后保持页面打开，等待图片上传和逐行处理结束，不要重复点击。

后端会逐行执行草稿创建或更新、图片处理、机器审核和发布编排。一行失败不会影响其他行，整批可能出现“部分成功”。

同一个包重新上传会得到同一个批次标识，用于幂等和续传；修改内容后重新打包，才会成为新批次。

## 6. 结果状态

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 已发布 | 角色已经上线 | 打开角色详情，核对名称、归属、立绘和更新内容 |
| 待复核 | 内容已创建，但暂不公开 | 到“内容复核”完成处置；这不是失败 |
| 被拒 | 机器审核终拒 | 按公开拒绝类别修改源包，重新打包提交 |
| 失败 | 格式、版本冲突或外部依赖异常 | 按行内提示处理；不确定时保留批次 ID 并联系研发 |

内容复核的处置会真实生效：

- `release`：放行内容。
- `confine`：限制内容。
- `purge`：永久清除内容，不可撤销。

## 7. 导入后的固定动作

1. 打开至少一个新建角色和一个更新角色的详情页，核对最终数据。
2. 如果有待复核行，通知复核同事并跟进处置结果。
3. 导出结果清单 CSV。结果清单只含标识、角色 ID、状态和错误，不含正文。
4. 按 `row_key` 把结果清单中的 `character_id` 回填到源 manifest。
5. 一起保存源 ZIP 和结果清单，作为下一次修订的起点。
6. 在“导入历史”确认本批可被找到，并能重新打开逐行结果。
7. Admin 在“操作审计”核对本批的操作人、时间、原因和批次 ID。

## 8. 修订与纠错

导入历史可以查看结果，但不能撤销整批导入。

修订流程：

1. 找到上一次保留的源包和结果清单。
2. 确认 manifest 已回填正确的 `character_id`。
3. 修改完整行内容；不要只保留想修改的字段。
4. 重新打包并预检，确认目标角色当前名称。
5. 作为新批次提交并重新完成结果核对。

如果出现版本冲突，说明角色在预检后被其他操作修改。必须重新上传并预检，不要直接重试旧提交。

## 9. 何时停止操作并联系研发

- 页面显示写入未启用、认证异常或权限异常。
- 批次长时间停留在运行中，结果计数与总行数不一致。
- 多次出现对象存储、图片处理或审核依赖异常。
- 同一包重复提交后出现重复角色或不一致的批次 ID。
- 更新目标名称、归属账号或角色 ID 与预期不一致。

联系研发时提供：批次 ID、操作时间、操作人、源包文件名、受影响的 `row_key` 和页面错误码。不要通过聊天工具发送角色正文或生产认证信息。
